# 检索协议（把论文库当参考依据时怎么查）

目标：在回答一个**非论文管理类**的问题时，用最少 token 找到库里真正相关的那一两篇。

## 三级渐进式检索（不要一上来就读全文）

| 级 | 动作 | 成本 | 什么时候停 |
|----|------|------|-----------|
| L0 | 读 `INDEX.md` | ~1 页 | 一眼看出没有相关论文 → 直接说"库里没有相关的工作"并正常回答，**不要硬蹭** |
| L1 | `library.py search "关键词"` 或 `Grep` 扫 `<id>/README.md` 的 frontmatter | 极低 | 命中 1–3 篇候选 → 进 L2 |
| L2 | 读候选的 `README.md` 正文（特性卡） | 中 | 确认相关 → 进 L3；不相关 → 回 L1 换词 |
| L3 | 读 `<id>/analysis.md` / `<fulltext>_extracted.txt` | 高 | 只在这条信息**必须精确**（具体公式、超参、数字）时才做 |

L0/L1 是默认动作；**L2 是常态终点**。绝大多数问题读到特性卡就够回答了。

## 关键词怎么选

1. **先抽问题里的实体名词**（`B-rep`、`点云`、`拓扑`、`Marching Cubes`），不用抽象词（`方法`、`效果`）。
2. 中文和英文各试一次——库里 tag 可能只写了其中一种。
3. 命中为空时，用 `library.py list` 看**库里实际有哪些 tag**，再用库里的词重搜，而不是继续瞎猜同义词。

```bash
python library.py search "B-rep 拓扑 连续"
python library.py search --tag GVD
python library.py search "watertight" --task 生成
```

## 引用规范（回答里必须让人能回溯）

借用了论文库里的内容，就在回答里**显式标注来源**，格式：

```
（依据 dualBrep 特性卡：GVD-UDF 把拓扑编码为连续场 → E:\parper\dualBrep\README.md）
```

- 说清是**哪篇**、**借了什么**，不要含糊地说"根据相关文献"。
- 如果只是**受启发**而不是论文里的原结论，必须写"受 X 启发的思路"，不要伪装成论文结论。
- 库里没有相关内容时，**明说没有**，然后用通用知识回答——不要把不相关的论文凑上来充数。

## 反向动作：一个问题答完，顺手补库

回答过程中如果发现某篇论文的 `reuse_when` / `tags` 明显漏了这次用到的场景，
**当场补进 frontmatter 并跑 reindex**。这是论文库唯一能长期保持可检索的方式——
检索失败一次，就修一次卡。

## 性能提示

- 库里论文 < 50 篇时，`INDEX.md` 全文读入即可，无需脚本。
- > 50 篇时，优先 `search`，`INDEX.md` 只读「按标签聚合」和「何时可复用」两节。
- 首次搜索不命中时**不要**直接 `Grep` 全文 —— `fulltext_*.txt` 单篇可达几百 KB，
  先用 `--tag` / `--task` 缩小范围，或读 `INDEX.md` 的聚合节。
